# Security and responsible disclosure

Do not submit credentials, API keys, tokens, private customer data, private logs, or exploit payloads in public issues.

For a suspected vulnerability in the LEGION collector, verifier, key-management process or evidence pipeline:
1. Do not publish exploit details or sensitive evidence in a public issue.
2. Use GitHub's private vulnerability reporting for this repository if enabled.
3. Include only the affected component, reproducible non-sensitive steps, and a safe contact route.

The public contract matrix is not a security certification. It tests selected read-only input-schema rules only. It does not assess authorization, prompt injection, data exposure, sandbox escapes, availability or other security properties.

Publisher correction and right-of-reply submissions belong in the public Publisher Correction issue template. A material adverse finding receives a 72-hour reply window before public escalation.

No runtime probing of private, paid, authenticated, destructive or state-changing endpoints is authorised by a public TLOG entry alone.
